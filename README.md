# AI Video Summarization Pipeline

## Whisper & GPT 기반 AI 영상 요약 백엔드 파이프라인

> 대용량 영상 파일을 업로드하면  
> 음성을 추출하고 일정 단위로 분할한 뒤 텍스트로 변환하며,  
> AI를 활용해 영상의 핵심 내용을 자동으로 요약하는  
> **AI 영상 분석 및 요약 백엔드 파이프라인 프로젝트**

---

## Project Overview

- **프로젝트 형태**: 개인 백엔드 프로젝트
- **주제**: AI 기반 영상 요약 파이프라인
- **핵심 기술**: FastAPI, ffmpeg, Whisper, GPT API
- **주요 관심 영역**
  - 대용량 영상 파일 처리
  - 단계별 AI 파이프라인 설계
  - 작업 상태 관리 및 장애 복구
  - AI 추론 자동화
  - 클라우드 기반 파일 저장 및 서비스 운영

---

## Project Goal

- 대용량 영상 파일을 안정적으로 업로드하고 처리할 수 있는 백엔드 구현
- 음성 인식과 요약 처리를 분리한 **단계별 AI 파이프라인 구축**
- 영상 업로드부터 텍스트 변환과 요약 생성까지 이어지는 자동 처리 흐름 구현
- 긴 영상도 처리할 수 있도록 오디오를 청크 단위로 분할
- 처리 중 오류가 발생하더라도 작업 상태를 확인하고 재처리할 수 있는 구조 설계
- 실제 서비스 적용을 고려한 저장소, 상태 관리 및 결과 관리 구조 구현

## Key Features

### Video Upload API

- FastAPI 기반 영상 업로드 REST API
- 대용량 영상 파일 업로드 처리
- 파일 형식 및 요청 데이터 검증
- 업로드된 영상의 작업 ID 생성
- 업로드 이후 비동기 처리 흐름으로 연결
- AWS S3 기반 원본 영상 저장

### Audio Extraction

- ffmpeg를 활용한 영상 내 음성 추출
- 음성 인식에 적합한 오디오 형식으로 변환
- 영상과 오디오 처리 과정을 분리하여 파이프라인 단계 명확화

### Audio Chunking

- 긴 오디오 파일을 일정 시간 단위의 청크로 분할
- 각 청크를 독립적으로 처리할 수 있도록 작업 단위 구성
- 대용량 음성 파일을 한 번에 처리할 때 발생할 수 있는 메모리 및 처리 시간 문제 완화
- 실패한 청크만 다시 처리할 수 있도록 재실행 가능성을 고려한 구조 설계

### Speech-to-Text

- OpenAI Whisper를 활용한 음성 인식
- 청크 단위로 음성 인식 작업 수행
- 각 청크의 변환 결과 저장
- 청크 순서를 기준으로 전체 자막 병합
- 일부 청크 실패 시 전체 작업을 다시 시작하지 않도록 처리 단계 분리

### AI Summarization

- GPT API를 활용한 영상 내용 자동 요약
- 병합된 전체 텍스트를 기반으로 핵심 내용 생성
- 영상의 주요 주제와 요점을 중심으로 요약
- 긴 텍스트 입력을 고려한 요약 요청 구조 설계
- 생성된 요약 결과 저장 및 조회 기능 구현

### Pipeline Orchestration

- 영상 처리 과정을 단계별 작업으로 구성
- 각 처리 단계의 시작, 진행, 완료, 실패 상태 관리
- 전체 작업과 청크 작업의 상태를 분리하여 관리
- 오류 발생 지점 확인이 가능한 구조
- 실패한 작업의 재처리를 고려한 파이프라인 설계
- 완료된 결과를 조회할 수 있는 API 흐름 구현

### File and Resource Management

- 원본 영상 및 결과 파일의 저장 경로 분리
- 처리 과정에서 생성되는 임시 오디오 파일 관리
- 작업 완료 또는 실패 이후 임시 파일 정리
- 불필요한 로컬 저장소 사용을 줄이기 위한 삭제 처리
- S3와 로컬 임시 저장소의 역할 분리

## Processing Flow

1. 사용자가 FastAPI 업로드 API를 통해 영상 파일을 전송합니다.
2. 서버는 영상 파일과 요청 데이터를 검증합니다.
3. 원본 영상 파일을 AWS S3에 저장합니다.
4. 영상 분석 작업을 생성하고 작업 상태를 기록합니다.
5. ffmpeg를 사용해 영상에서 음성을 추출합니다.
6. 긴 오디오를 일정 시간 단위의 청크로 분할합니다.
7. 각 청크의 처리 상태를 Redis에 저장합니다.
8. Whisper를 사용해 청크별 음성을 텍스트로 변환합니다.
9. 청크 순서에 따라 텍스트 결과를 하나로 병합합니다.
10. 병합된 텍스트를 GPT API에 전달해 핵심 요약을 생성합니다.
11. 전체 텍스트와 요약 결과를 데이터베이스 또는 S3에 저장합니다.
12. 처리 과정에서 생성된 임시 파일을 삭제합니다.
13. 사용자는 작업 상태 및 최종 요약 결과를 조회합니다.

## Job Status Flow

영상 처리 작업은 다음과 같은 상태로 관리하도록 설계했습니다.

```text
PENDING
  ↓
UPLOADED
  ↓
EXTRACTING_AUDIO
  ↓
CHUNKING
  ↓
TRANSCRIBING
  ↓
MERGING
  ↓
SUMMARIZING
  ↓
COMPLETED
```

처리 중 오류가 발생한 경우 다음과 같이 실패 상태를 기록합니다.

```text
FAILED
```

단계별 상태를 기록함으로써 사용자가 현재 처리 진행 상황을 확인할 수 있고,  
개발자는 오류가 발생한 단계를 빠르게 파악할 수 있도록 했습니다.

## Technical Challenges

### 대용량 영상 처리

대용량 영상 전체를 한 번에 처리할 경우 업로드 시간, 메모리 사용량,  
AI 추론 시간과 실패 복구 측면에서 문제가 발생할 수 있었습니다.

이를 해결하기 위해 영상 업로드, 음성 추출, 오디오 분할, 음성 인식,  
텍스트 병합, 요약 생성을 각각 독립된 단계로 분리했습니다.

특히 오디오를 청크 단위로 분할함으로써 다음과 같은 장점을 확보했습니다.

- 메모리 사용량 감소
- 긴 음성의 안정적인 인식
- 실패 청크 식별
- 특정 청크만 선택적으로 재처리
- 청크 단위 병렬 처리로 확장 가능한 구조

### 단계별 상태 관리

영상 분석은 여러 단계로 구성되며, 각 단계의 처리 시간이 길 수 있습니다.  
따라서 사용자가 요청 직후 결과를 받는 일반적인 동기식 API 구조는 적합하지 않았습니다.

Redis를 활용해 작업 상태를 관리하고, 각 처리 단계가 변경될 때마다 상태를 갱신하여  
사용자가 현재 처리 상황을 조회할 수 있도록 설계했습니다.

### 청크 결과 병합

각 청크는 독립적으로 음성 인식되기 때문에 결과를 단순히 저장하는 것만으로는  
전체 영상의 올바른 대본을 생성할 수 없습니다.

청크 생성 시 순서 정보를 함께 저장하고, 모든 처리가 완료된 후  
청크 순서를 기준으로 음성 인식 결과를 병합하도록 구현했습니다.

### 실패 복구

전체 작업을 하나의 긴 프로세스로 구현하면 후반 단계에서 오류가 발생했을 때  
처음부터 모든 작업을 다시 실행해야 하는 문제가 있습니다.

각 단계와 청크의 상태를 별도로 저장하여 실패 지점을 확인하고,  
이미 완료된 작업은 재사용할 수 있도록 파이프라인을 설계했습니다.

### 임시 파일 관리

영상과 음성 처리 과정에서는 원본 영상, 추출 오디오, 청크 파일 등  
여러 임시 파일이 생성됩니다.

작업 완료 및 실패 시 임시 파일을 정리하는 로직을 추가하여  
서버 저장 공간이 지속적으로 증가하지 않도록 했습니다.

## Design Considerations

### 음성 인식과 요약 처리 분리

Whisper 음성 인식과 GPT 요약은 서로 다른 목적과 실패 가능성을 가진 작업입니다.

두 단계를 분리하여 음성 인식이 완료된 이후 요약 단계만 다시 실행하거나,  
요약 모델과 프롬프트를 변경하더라도 기존 음성 인식 결과를 재사용할 수 있도록 했습니다.

### 저장소 역할 분리

- **S3**: 원본 영상과 대용량 결과 파일 저장
- **RDS**: 작업 정보, 상태 및 최종 결과 메타데이터 저장
- **Redis**: 빠르게 변경되는 작업 진행 상태와 청크 상태 관리
- **Local Storage**: ffmpeg 및 Whisper 처리에 필요한 임시 파일 저장

데이터 특성에 따라 저장소 역할을 분리함으로써  
파일 저장, 영속 데이터, 일시적 상태 관리의 책임을 명확히 했습니다.

### 비용과 처리 성능

AI 영상 처리에서는 모델 품질뿐 아니라 처리 시간과 API 비용도 중요합니다.

다음 항목을 비교하며 구조를 설계했습니다.

- 오디오 청크 길이
- Whisper 모델 크기
- 음성 인식 처리 시간
- 요약 요청의 입력 토큰 수
- 요약 품질
- API 호출 비용
- 오류 발생 시 재처리 범위
